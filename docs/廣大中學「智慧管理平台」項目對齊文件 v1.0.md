## 1. 項目背景


| 項目   | 內容                                      |
| ---- | --------------------------------------- |
| 試點學校 | 廣大中學（澳門私立中學）                            |
| 決策人  | 校長（項目由他**主動**提出，非我方推銷）                  |
| 關係基礎 | 團隊成員之一為校長之子                             |
| 參照對象 | 勞校系統（由**勞校校長本人**自建，已跑數年）——廣大校長主動提起，想親眼看 |
| 現場資源 | 已約勞校工作人員，當天可開啟勞校系統展示                    |
| 市場   | 澳門約 68 私校 + 8 公校，可規模化                   |
| 待確認  | 校董會是否需過會？預算週期？                          |


### 客戶痛點（他自己的話 — 全案基石）

1. 家長會時**調不出學生完整記錄**，好壞都缺數據佐證
2. **出差在外不知道學校今天狀況**（出勤、請假、教師狀態）
3. **好老師一走，他的東西就跟著走了**
4. 決策靠主觀印象（評選班長、教師任用、政策成效驗證）
5. 數據散在多系統與 Excel，重複輸入、非實時、難互通

### 已知 vs 未知

**未知（Phase 0 要查）**：現有系統清單、供應商或自建、哪些仍是紙本、**學生/教師編號各系統是否一致（決定能否打通的關鍵）**、歷史數據年限、有無 IT 人員、過去是否嘗試失敗過

> ⚠️ **團隊紀律：當天不報架構、不報價。** 標準答案：「我還不知道貴校數據長什麼樣，現在報價的都是在猜。」

## 2. 定位與差異化

> **把「懂學校」這件事，從一個人的手藝，變成一間學校的資產。**


| 對手         | 問題                 | 我們          |
| ---------- | ------------------ | ----------- |
| 大廠標準化產品    | 不懂澳門學校日常           | 貼地 + 駐校陪跑   |
| 勞校模式（校長自建） | 一個人的作品，無團隊、無文檔、無傳承 | 有團隊、可傳承、可對接 |
| 學校找老師自己做   | 無權調動部門、還要教書、易半途而廢  | 全職團隊 + 校長授權 |
| 現有分散供應商    | 各做一塊，互不打通          | 以「互通」為核心    |

## 4. 核心論證鏈（全場骨架，五句話）

1. 「這件事做得成，勞校已經證明了。」
2. 「勞校做得成，關鍵不是技術強，是做的人**徹底懂學校**。」
3. 「但勞校那套是**一個人的作品**，不是**一間學校的資產**——人一走就懸空。您要的是二十年後還在的東西。」
4. 「所以要成，需要兩樣同時具備：**懂學校 + 有團隊**。」
5. 「而您剛才看到的東西，我們沒收一毛錢就先做出來了。這就是我們現在能給您的全部證明。」

> 第 2、4 點是「兒子在團隊」唯一出場處——**打領域理解牌，不打感情牌**。全場提一次。

## 5. 當天流程與關鍵話術（75–80 分鐘）



### 【0–8′】開場（先遞紀要 + Roadmap + 立項書）

> 「這些先給您——**不管後面合不合作，都是您的。**」
>
> 「我把您上次說的三句話記下來了：一，家長會調不出學生完整記錄；二，您出差在外不知道學校今天出勤怎麼樣；三，好老師一走東西就跟著走了。**這三句話是我們這幾天所有工作的依據。** 我理解得對嗎？」



### 【8–25′】勞校系統（他想看的，讓他看夠）

> 「先講清楚三件事：**一，這不是我們做的**，是勞校校長自己做的，我很佩服。**二**，請人來只是讓您先有個具體概念。**三**，用測試帳號，勞校真實數據不會出現——**將來廣大的數據我們也是同樣規矩。**」

⚠️ 全程不點評、不比較、不追問勞校同事。

### 【25–30′】轉場（關鍵 5 分鐘）

> 「所以這件事在澳門是**做得成的**，不是空想。」
> 「而勞校最值得學的是——它證明了做學校系統，卡住的從來不是技術，是**懂不懂學校**。」
> 「但那是**一個人的作品**，不是**一間學校的資產**。哪天那位校長不做了，誰接手？」
> 「那問題就簡單了——**廣大應該長成什麼樣子。** 這幾天我們試著畫了一下。」



### 【30–48′】Prototype + Roadmap（主菜）

> 「先說明，這**不是產品，是構想稿**。目的不是給您驗收，是**請您指著螢幕告訴我們哪裡不對**。您今天說要改，我們回去就改。」

**（把手機遞給他，讓他自己點，不要講解）** 只問三種問題：

- 「如果明天早上八點您在機場打開這一頁，**最想先看到哪三個數字？**」
- 「這個學生檔案，家長坐在您對面時，**哪一塊是您最需要、但現在最調不出來的？**」
- 「這裡放了『欠交功課次數』——**這個數字現在是誰在記？記在哪？**」



### 【48–55′】核心論證五句話



### 【55–65′】主動預警風險（含金量最高）

> 「有三件事我想主動講。這是這類項目最常死掉的原因，**我寧願現在講難聽的。**」

**① 老師**：「教師評估技術上做得到。但第一期就打這張牌，變成『校長要監控我們』，我們永遠拿不到數據。建議第一期對外只講四個字：**幫老師減負**。評估功能照做，權限只開給您，不宣傳、不進考核。」

**② 紙本**：「我不會答應把所有紙本都錄進系統，那是無底洞，也是很多項目爛尾的真正原因。先抽一個班、一個學期試算成本。」

**③ 合規**：「澳門有《個人資料保護法》，學生資料屬敏感個資，涉及轉去澳門以外伺服器是有規定的。我們會先查清楚再給方案，**不會讓您事後被人問到答不出來。**」

> 「所以今天我**不會**給您技術架構，也**不會**給您報價。因為我還不知道貴校數據長什麼樣。**現在就能報價的都是在猜。**」



### 【65–72′】數據來源假設表 → 順勢盤點九問

1. 成績、品行、出勤分別記在哪？同一個系統嗎？
2. 是外面買的、學校自建，還是 Excel？
3. 誰在維護？有 IT 人員嗎？
4. 老師每週要填哪些表？填在哪？
5. 哪些現在還是紙？
6. 歷史數據追得到幾年前？
7. 招生、學位、升學誰在管？
8. 有哪個系統是「大家都嫌難用但不得不用」的？
9. ⭐ **最近三年有沒有試過改善但沒成的？當時卡在哪？**



### 【72–80′】收尾

> 「今天我不跟您要決定、不跟您要錢。我只要三樣，都不花錢：
> **一，** 一位有權調動人的同事當總協調人（建議教務主任層級）；
> **二，** 一張授權紙，讓我們去問各系統負責人、開幾個**唯讀**帳號，只看不改，看完交回；
> **三，** 四個星期後的今天坐下來，我交一份《數據現況地圖》給您，**無論合不合作，無條件是學校的**。
> 第三樣現在就能定——**您行事曆方便嗎？**」

**時間壓力**：「要趕九月新學年，八月試運行、六月開發完、五月定方案——**盤點得在 X 月前開始。錯過就是再等一整個學年，中間又走一屆畢業生的數據。**」

**稀缺（給理由）**：「**我們接下來只會全力投一間學校做深度陪跑。** 第一家範圍您定、優先級您排、駐校成本我們吃、價格永久鎖定。這不是話術——**從第二家開始我們就是標準化交付，做不到這樣。**」

**喜好（全場唯一一次）**：「最後講句私人的。**別的供應商做砸了您換一家，我們做砸了跑不掉。** 所以商務對口和簽約由 XXX 負責，讓 [兒子] 專心做技術，該迴避的迴避。您對校董會交代也好講——先導試點、只做盤點、不滿意隨時終止、報告無條件歸學校。」

## 6. 絕對不要說的五句話


| ❌               | 原因                       |
| --------------- | ------------------------ |
| 「對您沒有任何成本和損失」   | 不是真的。改成誠實報出他的成本          |
| 「我們需要這個項目來打入市場」 | 那是你的需求。改成「用超額投入換首家案例權」   |
| 「免費幫您做」         | 免費＝不值錢＋沒人重視＋你沒立場要資源      |
| 反覆提父子關係         | 每提一次就多提醒他一次利益衝突          |
| 任何貶低勞校校長的話      | 同行且大概率認識。問題歸給**結構**，不歸給人 |




## 7. FAQ 演練（每人要背）


| 他問          | 答案要點                                                              |
| ----------- | ----------------------------------------------------------------- |
| 那我叫學校老師自己做？ | 「可以問勞校校長花了多少個晚上。他做時是**校長**，能拍板調部門；您的老師沒這個權還要教書。半途停下的學校系統，澳門不是沒有。」 |
| 你們幾個人做得完？   | 具體人數+分工。「MVP 範圍是照我們產能設計的，不是照理想設計的。」                               |
| 老師會反感嗎？     | 第一期只講「幫老師減負」，評估權限只開給校長                                            |
| 紙本怎麼辦？      | 不做全量，先抽一班一學期試算成本                                                  |
| 數據放哪安全？     | 學校機房無專職 IT、無異地備份、USB 就能拷走。折衷：**雲端為主 + 每日全量備份落地學校 NAS**            |
| 多少錢？        | Phase 0 象徵性費用可抵扣，**正式報價等現況地圖出來後兩週內給**                             |
| 做到一半你們跑了？   | 源碼託管 + 數據隨時全量導出 + 階段獨立驗收 + 文檔交付，寫進 MOU                            |
| 怎麼跟校董會交代？   | 給現成話術 + 主動說「歡迎找兩家對照報價」                                            |

## 9. Prototype 開發規格（給 AI Agent）



### 9.1 Agent Prompt

```
# 任務
為澳門「廣大中學」開發智慧管理平台的高保真可點擊原型，用於向校長演示。
純 Demo，不需後端、不需資料庫。

# 技術
- Next.js 14 (App Router) + TypeScript + Tailwind CSS + shadcn/ui
- 圖表 Recharts，圖示 lucide-react
- 所有資料放 /lib/mock-data.ts，純前端 mock
- 部署 Vercel，一個 URL 手機瀏覽器可開
- 全繁體中文（澳門用語）
- Mobile-first：必須在 iPhone Safari 完美顯示

# 設計原則
- 專業、克制、可信。像真實在運作的管理系統，不像 Dribbble 作品
- 主色深藍灰 (#1e3a5f 系) + 白底 + 狀態色（綠正常/橙注意/紅異常）
- 大數字、卡片式佈局、清楚層級
- 不要漸層、炫光、3D、過度動畫

# 必須完整打通的唯一互動路徑
首頁駕駛艙 → 點「出勤異常班級」 → 班級360 → 點某學生 → 學生360 → 
切「六年趨勢」Tab → 看到跨年度數據

# 絕對不要做（不打動人，一個都不要花時間）
登入頁、註冊、忘記密碼、設定頁、個人資料編輯、權限管理介面、
任何「功能開發中」空白頁、深色模式切換

# 未做功能的處理
點了顯示溫和 toast「Phase 2 功能」，不要空白頁或 404
```
